2. TECH STACK
--------------------------------------------------------------------------------
- Framework: Next.js (App Router, React 18/19, TypeScript)
- Styling: Tailwind CSS

- DB Client: Supabase JS (@supabase/supabase-js, @supabase/ssr)

3. USER FLOW & ROLE ARCHITECTURE
--------------------------------------------------------------------------------

[A] LOGIN & PIN VERIFICATION:
- Input Fields:
  1. Login ID: Exactly 3 uppercase letters followed by 5 digits (e.g. JDG10001, MNR20001).
  2. PIN: Numeric passcode (e.g., 1234).
- System Validation:
  - Checks format `^[A-Z]{3}[0-9]{5}$`.
  - Matches ID and PIN against the Supabase `profiles` table.
- Role Splitting by Prefix:
  * "JDG*****" -> JUDGE ROLE:
    Full access to dashboard, team details, scoring tables, draft saving, and final submissions.
  * "MNR*****" -> MENTOR ROLE:
    Viewer access. Can browse rounds, view teams and team details.
    The evaluation tab and scoring actions are FROZEN, INACTIVE, and READ-ONLY.

[B] JUDGE DASHBOARD:
- Step 1: Displays hackathon evaluation rounds as interactive cards (e.g., Round 1, Round 2).
- Step 2: Selecting a round displays all teams allotted to that round.
- Layout Style: Windows OS "Content View" (clean horizontal rows/cards displaying
  metadata clearly, similar to Windows file explorer content view).
- Each Team Card Displays:
  - Team Name (e.g., ByteCrafters)
  - Team ID (e.g., VV-101)
  - Realtime Evaluation Status Button/Badge:
    * ⚪ "Not Evaluated" (initial state)
    * 🟡 "Saved as Draft" (evaluator started, can still edit)
    * 🟢 "Submitted" (finalized, locked)

[C] TEAM ASSESSMENT SCREEN (DUAL-TAB VIEW):
Clicking on any team opens a detailed assessment page or modal with two side-by-side tabs:

  TAB 1: TEAM DETAILS (Visible to both Judges and Mentors)
  --------------------------------------------------------
  - Header: Team Name and Team ID.
  - Team Members: List of members and their respective academic branches (e.g., CSE, AIML).
  - Selected Domain: Retrieved from database (e.g., Artificial Intelligence, FinTech).
  - Case Study: Selected problem statement during the event (from database).
  - Canva PPT Link: Direct clickable/embeddable presentation link (from database).
  - Google Drive Link: Prototype link if provided (from database).
  - Presentation: Clean, modern, highly organized card layout.

  TAB 2: EVALUATION & SCORING (Active for Judges, Frozen for Mentors)
  ------------------------------------------------------------------
  - Dynamic Criteria Matrix: Fetched dynamically from Supabase `evaluation_criteria`.
  - Table Structure:
    Criteria Name & Description | Max Marks | Marks Allotted
  - Grand Total Row:
    Auto-computes: Grand Total Max vs. Obtained Marks in real-time.
  - Action Controls:
    * "Save Draft": Saves current entered scores to Supabase with status = 'draft'.
      Judge can return later to review or change marks.
    * "Edit": Unlocks the fields for editing when a draft exists.
    * "Submit Evaluation": Permanently locks the evaluation (status = 'submitted').
      Cannot be edited after submission.
    * Realtime Sync: Changes immediately update the status badge on the dashboard.
  - MENTOR GUARD: If logged in as MNR, this tab shows an explanatory message:
    "Mentor Mode: Evaluation scoring is restricted to authorized judges."
    All input fields and action buttons are disabled/hidden.

4. DATABASE ARCHITECTURE (SUPABASE)
--------------------------------------------------------------------------------
All tables, relations, and sample seeds are ready in `SUPABASE_STEPS.txt`.

Summary of Tables:
1. `profiles`: Stores `login_id` (JDG/MNR + 5 digits), `pin`, `full_name`, and `role`.
2. `rounds`: Stores round number, name, description, active status.
3. `teams`: Stores team ID, name, domain, case study topic, Canva link, Drive link.
4. `team_members`: Stores member names, academic branches, lead status.
5. `round_teams`: Maps teams to specific evaluation rounds.
6. `evaluation_criteria`: Stores admin-configured criteria and maximum marks per round.
7. `evaluations`: Stores judge evaluation state ('draft' vs 'submitted'), total score, feedback.
8. `evaluation_scores`: Stores itemized scores per criterion.

Realtime Enabled:
`ALTER PUBLICATION supabase_realtime ADD TABLE public.evaluations;`
